# Changelog

## Изменения на 2026-10-05

### Что сделано
- Исправлена логика табеля сотрудников в WPF и доменной модели:
  - устранены дубли строк при повторном добавлении сотрудника;
  - исправлены неверные итоги по строкам и по табелю;
  - устранена ошибка, при которой комментарии сохранялись не в тот день;
  - исправлено поведение при сохранении и загрузке состояния табеля.
- Доведена до рабочего состояния прикладная логика API:
  - операции получения, сохранения, добавления строки и обновления комментария реализованы согласованно;
  - добавлена валидация периода и проверка уникальности сотрудников;
  - запрет изменения утверждённого табеля (Approved) возвращает понятную ошибку 409 Conflict.
- Подключён WPF-клиент к API и приведён к единой модели данных.
- Добавлены автоматические тесты на доменную логику, WPF-сценарии и API.

### Проверка
- Выполнена сборка решения: `dotnet build TimesheetCandidateTask.sln`
- Выполнены тесты: `dotnet test TimesheetCandidateTask.sln`
- Результат: 35/35 тестов успешно пройдены.

### Документация по тестам
- `TimesheetPeriodTests` — проверяют корректный расчёт часов и итогов по строкам и периоду.
- `TimesheetWpfUnitTests` — проверяют поведение ViewModel: загрузку, добавление сотрудников, сохранение комментариев, утверждение табеля и отображение ошибок.
- `TimesheetApiUnitTests` — проверяют серверную логику API: сохранение табеля, обновление комментариев и обработку ошибок при отсутствии данных.
- `TimesheetViewModelApiIntegrationTests` — проверяют интеграцию WPF/ViewModel с HTTP API, включая сценарии сохранения и запрет изменений после утверждения.

### Принятые допущения
- Под требованием не переписывавать legacy-код подразумевалось использование существующих классов и методов, без изменения их сигнатур и логики, за исключением исправления ошибок.
- RetailId прописывается в appsettings.json WPF-клиента и API, а также в тестах.
- При нажатии кнопки "Добавить сотрудника" в WPF-клиенте добавляется сотрудник с фиксированным именем и идентификатором, из статической коллекции.
- При нажатии кнопки "Добавить сотрудника" прописываетсяя 8 часов 1 января как рабочее время, 8 часов 2 января как праздничный день и 0 часов 3 января как выходной день.
- При нажатии кнопки "Загрузить" в WPF-клиенте загружается табель из API по RetailId, указанным в appsettings.json и захардкоженному периоду 01-01-2026.
- Если табель не найден, создаётся предзаполненный табель с Ивановым И.И
- В WPF отображаются только два даты месяца (01.01 и 02.01), остальное не требуется для текущего сценария.
